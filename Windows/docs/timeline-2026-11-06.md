# Layer animation timeline — November 6, 2026

## Delivered behavior

Open **View > Timeline** and choose **Create layer animation timeline**. The default timeline is
120 frames at 24 fps. The panel includes:

- A playhead, play/pause, stepping, loop, duration, frame rate, zoom and fit controls.
- One visible-time clip per layer. Drag the edges to trim; drag its body to move the clip and keys.
- Position X/Y, scale X/Y, rotation and opacity keyframes. Drag diamonds to move keys.
- Linear, smoothstep and hold interpolation; field edits and timeline edits support Undo/Redo.
- PNG sequence export on a worker, with progress and cancellation. A completed sequence includes
  `sequence.json` with its frame rate and filename pattern.
- `editor_timeline` through MCP, plus timeline state and current-frame preview/PNG export.

Playback evaluates metadata and shares source image/mask buffers. It reuses compositor caches,
follows display-frame callbacks and coalesces pending seeks while rendering is busy. A completed
frame remains publishable during scrubbing; the next render takes the latest requested time.
Seeking and playback do not create document history.
Animation preview protects the base canvas from ordinary edits; switch off **Animation preview**
or close the panel to edit the base artwork. The timeline is saved in the `.comp` manifest.

This release does not implement audio, video clips, MP4/GIF encoding or folder transform keys.
Folder and adjustment tracks support opacity and visible time. In points are inclusive, out points
exclusive. Rotation keys may contain multiple turns; position keys use absolute document centers,
and scale keys multiply the base layer dimensions.

## Format compatibility

Creating animation upgrades that document to format v12 in the same Undo step. New static
documents remain v11. Current macOS builds support v1–11 and reject v12 rather than discard its
animation. Clearing animation does not downgrade a v12 document. See
[the shared format specification](../../docs/project-format.md#version-12-layer-animation-windows).

## November 8 interaction follow-up

The 16 ms DispatcherTimer produced only about 32 submitted frames per second on the local
60 fps scene. Playback now runs from `CompositionTarget.Rendering`, uses elapsed time to select
the frame and avoids refreshing an unchanged playback frame. Pausing or retiring a document
unsubscribes the callback. Seeking no longer changes the document render revision, so a newer
seek cannot discard every completed frame; content changes and preview-mode switches still
invalidate old render work. Seeking with Animation preview disabled does not render the unchanged
base image.

### Additional pointer and control refresh work

The broader follow-up separates frame changes from structural/control-state changes. Seeking
updates the time label, animated values and interpolation without rewriting permissions, clip
fields or scroll ranges. Unchanged values are retained, and repeated input within the same frame
does not invalidate the timeline. Pointer motion keeps only the latest position for the next
display callback; release flushes the final position before committing one key/clip history step.
Key dragging preserves the pointer's grab offset. Cancel, panel close, document replacement and
window close retire queued input. High-resolution scrolling retains fractional rows, with matching
hit testing, instead of rounding small deltas away.

The saved Lime variant of the same 18-layer scene was measured in Debug:

| Observation | Before this follow-up | After |
| --- | ---: | ---: |
| Median UI time for 16 inputs within one snapped frame | 1.595 ms | 0.121 ms |
| Complete control refreshes for 960 inputs | 960 | 0 |
| Redraws from 12 repeated inputs at an unchanged time | 12 | 0 |
| Median single seek handling time | 0.321 ms | 0.127 ms |

The 960-input measurement groups 16 requests per display interval. It measures UI handler work,
not end-to-end pointer-to-display latency. Track drawing remains approximately 0.4–0.5 ms locally;
this change adds no track bitmap cache. The final normal GPU run published about 60 frames/sec.
A separate baseline with `COMPOSITOR_REQUIRE_GPU_PREVIEW=1` fenced GPU completion via a one-pixel
readback: median submit-plus-completion was 4.30 ms while seeking and 3.58 ms during playback.
Those fenced timings must not be confused with the earlier 0.15 ms command-submission measurement.

The same-frame regression failed before the product change and passed afterward. The expanded
app probe passed all 13 groups with GPU preview and with forced CPU rendering. It covers final
scrub position, key/clip release before a display tick, one-step Undo,
off-center key grabs and queued-input cancellation, in addition to the earlier checks.
Evidence uses the `timeline-interaction-20261108-ui-*` prefix under the existing artifact directories.
The forced CPU run passed correctness; this scene published about 12.7 frames/sec in that run.
Release PID 47844 passed real mouse play/pause, ruler drag (final frame 449), fractional scrolling,

Key and clip drags retain the existing canvas semantics: the committed animation changes at

### Independent time pointer

The blue time pointer is now a retained XAML overlay above the track drawing. While scrubbing,
its transform follows the raw pointer position immediately, including motion within one frame;
canvas evaluation still samples integer frames and coalesces pending requests. Release snaps the
pointer to the committed frame. Key dragging retains its grab offset. Pointer movement alone no
longer redraws the track text and clips; the canvas invalidates when a key highlight or drag changes.

Playback uses an independent linear RenderTransform animation synchronized to the playback clock.
Scroll/zoom restarts it at the current elapsed time, and pause/document replacement stops it.
This makes pointer motion continuous while image previews retain their existing rendering cadence.

The new regression first failed with 7.2 pixels of pointer lag for 12 subframe inputs at 30 px/frame.
It passed with maximum retained-geometry error below 0.00002 pixels before a display callback or
frame render was required. That checks the UI transform, not hardware input-to-photon latency.
The expanded probe passed all 14 groups with GPU preview and forced CPU rendering. Evidence uses
`timeline-interaction-20261108-pointer-*` under the existing artifact directories.
Release PID 34460 passed native Play and the moving pointer was observed; MCP confirmed playback
and a clean stop. Native scrubbing was not repeated for this build. Its file hashes and the
separate GPU/CPU scope are recorded in `Windows/artifacts/timeline-interaction-20261108/pointer-verification.json`;
the earlier `ui-verification.json` describes the preceding build.
